Importar carteirinhas pela aplicação, com validação no banco

A planilha de carteirinhas do cliente era carregada direto no banco pelo DBA. A importação passou para a aplicação, e o banco ficou responsável por decidir, linha a linha, o que entra, o que troca e o que é recusado — e por explicar o motivo.

Caso real, com a solução no banco desenvolvida por Daniele de Lima Matos. Os nomes de tabelas e colunas foram trocados por exemplos genéricos. Os scripts mostram a técnica em T-SQL; adapte nomes, tipos e regras ao seu modelo e teste em homologação antes de rodar em produção.

Resumo do caso

Problema
A importação das carteirinhas dos indivíduos era feita pelo analista de banco de dados, direto no banco, a partir da planilha enviada pelo cliente.
Ação
A aplicação ganhou uma tela para importar a planilha para uma tabela do banco. Um gatilho (trigger) nessa tabela valida cada linha: recusa carteirinha que já pertence a outro indivíduo, desativa a carteirinha anterior quando chega uma nova, registra a data da importação e grava um log com a situação de cada linha.
Resultado
As carteirinhas passaram a ser importadas pela própria aplicação. Quando havia algum ponto de atenção, o banco gerava um log e a aplicação mostrava o aviso ao usuário final.

O problema: a carga dependia de uma pessoa

Importar direto no banco funciona enquanto a planilha vem certa e o DBA está disponível. Com o tempo, os riscos aparecem:

  • Cada nova planilha vira um pedido para o DBA, e o cliente espera a fila.
  • Um número de carteirinha que já pertence a outro indivíduo pode entrar sem ninguém perceber.
  • O indivíduo que recebe uma carteirinha nova pode ficar com duas ativas.
  • Não fica registrado quando cada carteirinha entrou, nem o que foi recusado e por quê.

Só levar a importação para a aplicação não resolve: a planilha continua podendo trazer os mesmos erros. A importação precisa vir junto com as regras.

As regras da importação

Antes de escrever qualquer código, cada situação possível de uma linha da planilha ganhou uma decisão e um registro no log:

O que o banco faz com cada linha da planilha.
Situação da linha O que o banco faz Situação no log
Carteirinha nova, indivíduo sem carteirinha ativaInsere a carteirinha já ativaIMPORTADA
Carteirinha nova, indivíduo com carteirinha ativaDesativa a anterior e insere a nova ativaTROCA
Carteirinha já cadastrada para o mesmo indivíduoNão altera nadaJA_CADASTRADA
Carteirinha já cadastrada para outro indivíduoNão importaRECUSADA
Indivíduo que não existe no cadastroNão importaRECUSADA
Número repetido na própria planilha, ou indivíduo com duas carteirinhas novasNão importa nenhuma das linhas envolvidasRECUSADA

As duas últimas linhas da tabela não estavam no pedido original, mas aparecem em qualquer planilha preenchida à mão. Decidir antes evita que o banco escolha sozinho qual das linhas repetidas vale.

A ação, passo a passo

1. Cadastro, área de importação e log

São três tabelas com papéis separados. A Carteirinha é o cadastro oficial. A ImportacaoCarteirinha recebe as linhas da planilha exatamente como vieram, pela aplicação. A LogImportacaoCarteirinha guarda o que aconteceu com cada linha. A tabela Individuo já existia no sistema.

T-SQL 

        
-- Cadastro oficial: uma linha por carteirinha, ativa ou não
CREATE TABLE dbo.Carteirinha (
  CarteirinhaID     INT IDENTITY(1, 1) PRIMARY KEY,
  IndividuoID       INT          NOT NULL REFERENCES dbo.Individuo (IndividuoID),
  NumeroCarteirinha VARCHAR(30)  NOT NULL,
  Ativa             BIT          NOT NULL,
  LoteID            INT          NULL,
  DataImportacao    DATETIME2(0) NOT NULL,
  DataDesativacao   DATETIME2(0) NULL
);

-- Área de importação: recebe as linhas da planilha enviadas pela aplicação
CREATE TABLE dbo.ImportacaoCarteirinha (
  ImportacaoID      INT IDENTITY(1, 1) PRIMARY KEY,
  LoteID            INT          NOT NULL,
  IndividuoID       INT          NOT NULL,
  NumeroCarteirinha VARCHAR(30)  NOT NULL,
  UsuarioAplicacao  VARCHAR(100) NOT NULL,
  DataImportacao    DATETIME2(0) NOT NULL DEFAULT SYSDATETIME()
);

-- Log: uma linha para cada linha da planilha, com a situação e o motivo
CREATE TABLE dbo.LogImportacaoCarteirinha (
  LogID             INT IDENTITY(1, 1) PRIMARY KEY,
  ImportacaoID      INT           NOT NULL,
  LoteID            INT           NOT NULL,
  IndividuoID       INT           NOT NULL,
  NumeroCarteirinha VARCHAR(30)   NOT NULL,
  Situacao          VARCHAR(20)   NOT NULL,
  Mensagem          NVARCHAR(400) NOT NULL,
  DataLog           DATETIME2(0)  NOT NULL
);

      

    

    
O LoteID identifica cada planilha enviada: a aplicação gera um número por arquivo, e é por ele que a tela de importação consulta o resultado. A carteirinha desativada não é apagada — fica com Ativa = 0 e a data de desativação, e o histórico do indivíduo continua completo.


    
2. Regras que o próprio banco garante

    
Duas regras não podem depender só do gatilho: um número de carteirinha pertence a um único indivíduo, e cada indivíduo tem no máximo uma carteirinha ativa. Índices únicos garantem isso para qualquer caminho de escrita, inclusive uma correção manual feita direto no banco:

    

      

        T-SQL
        
      

      

        

        
-- Um número de carteirinha pertence a um único indivíduo
CREATE UNIQUE INDEX UX_Carteirinha_Numero
  ON dbo.Carteirinha (NumeroCarteirinha);

-- Cada indivíduo tem no máximo uma carteirinha ativa
CREATE UNIQUE INDEX UX_Carteirinha_UmaAtiva
  ON dbo.Carteirinha (IndividuoID)
  WHERE Ativa = 1;

-- A tela da aplicação consulta o log por lote
CREATE INDEX IX_LogImportacao_Lote
  ON dbo.LogImportacaoCarteirinha (LoteID);

      

    

    
O segundo é um índice filtrado: a unicidade vale só para as linhas com Ativa = 1, então o indivíduo pode ter quantas carteirinhas inativas precisar. Para gravar numa tabela com índice filtrado, a sessão precisa de QUOTED_IDENTIFIER ON e ANSI_NULLS ON — o padrão dos drivers atuais, mas vale conferir em aplicações antigas.


    
3. O gatilho que valida cada linha

    
O gatilho dispara depois que a aplicação grava as linhas da planilha na área de importação. Ele classifica cada linha, desativa as carteirinhas que vão ser trocadas, insere as novas e grava o log — tudo na mesma transação da importação.

    

      

        T-SQL
        
      

      

        

        
CREATE OR ALTER TRIGGER dbo.trg_ImportacaoCarteirinha_Validar
ON dbo.ImportacaoCarteirinha
AFTER INSERT
AS
BEGIN
  SET NOCOUNT ON;

  DECLARE @agora DATETIME2(0) = SYSDATETIME();

  -- 1. Classifica cada linha da planilha
  WITH linhas AS (
    SELECT
      i.ImportacaoID, i.LoteID, i.IndividuoID, i.NumeroCarteirinha,
      ind.IndividuoID         AS IndividuoCadastrado,
      c.IndividuoID           AS DonoCarteirinha,
      atual.CarteirinhaID     AS AnteriorID,
      atual.NumeroCarteirinha AS AnteriorNumero,
      COUNT(*) OVER (PARTITION BY i.NumeroCarteirinha) AS RepeticoesNumero,
      SUM(CASE WHEN c.CarteirinhaID IS NULL THEN 1 ELSE 0 END)
        OVER (PARTITION BY i.IndividuoID) AS NovasDoIndividuo
    FROM inserted AS i
    LEFT JOIN dbo.Individuo AS ind
      ON ind.IndividuoID = i.IndividuoID
    LEFT JOIN dbo.Carteirinha AS c
      ON c.NumeroCarteirinha = i.NumeroCarteirinha
    LEFT JOIN dbo.Carteirinha AS atual
      ON atual.IndividuoID = i.IndividuoID
     AND atual.Ativa = 1
  )
  SELECT
    ImportacaoID, LoteID, IndividuoID, NumeroCarteirinha, AnteriorID,
    CASE
      WHEN IndividuoCadastrado IS NULL    THEN 'RECUSADA'
      WHEN RepeticoesNumero > 1           THEN 'RECUSADA'
      WHEN DonoCarteirinha <> IndividuoID THEN 'RECUSADA'
      WHEN DonoCarteirinha = IndividuoID  THEN 'JA_CADASTRADA'
      WHEN NovasDoIndividuo > 1           THEN 'RECUSADA'
      WHEN AnteriorID IS NOT NULL         THEN 'TROCA'
      ELSE 'IMPORTADA'
    END AS Situacao,
    CASE
      WHEN IndividuoCadastrado IS NULL
        THEN N'Indivíduo não encontrado no cadastro. A carteirinha não foi importada.'
      WHEN RepeticoesNumero > 1
        THEN N'Número de carteirinha repetido na planilha. Nenhuma das linhas foi importada.'
      WHEN DonoCarteirinha <> IndividuoID
        THEN CONCAT(N'Carteirinha já cadastrada para o indivíduo ', DonoCarteirinha, N'. Não foi importada.')
      WHEN DonoCarteirinha = IndividuoID
        THEN N'Carteirinha já cadastrada para este indivíduo. Nada foi alterado.'
      WHEN NovasDoIndividuo > 1
        THEN N'Indivíduo com mais de uma carteirinha nova na planilha. Nenhuma foi importada.'
      WHEN AnteriorID IS NOT NULL
        THEN CONCAT(N'Carteirinha importada e ativada. A anterior (', AnteriorNumero, N') foi desativada.')
      ELSE N'Carteirinha importada e ativada.'
    END AS Mensagem
  INTO #analise
  FROM linhas;

  -- 2. Desativa a carteirinha anterior de quem recebeu uma nova
  UPDATE c
  SET Ativa = 0,
      DataDesativacao = @agora
  FROM dbo.Carteirinha AS c
  JOIN #analise AS a
    ON a.AnteriorID = c.CarteirinhaID
  WHERE a.Situacao = 'TROCA';

  -- 3. Insere as carteirinhas novas, já ativas e com a data da importação
  INSERT INTO dbo.Carteirinha (IndividuoID, NumeroCarteirinha, Ativa, LoteID, DataImportacao)
  SELECT IndividuoID, NumeroCarteirinha, 1, LoteID, @agora
  FROM #analise
  WHERE Situacao IN ('IMPORTADA', 'TROCA');

  -- 4. Registra a situação de cada linha para a aplicação
  INSERT INTO dbo.LogImportacaoCarteirinha
    (ImportacaoID, LoteID, IndividuoID, NumeroCarteirinha, Situacao, Mensagem, DataLog)
  SELECT ImportacaoID, LoteID, IndividuoID, NumeroCarteirinha, Situacao, Mensagem, @agora
  FROM #analise;
END;

      

    

    
Três cuidados sustentam esse gatilho:

    
    
      
  • Ele trata o lote inteiro de uma vez. No SQL Server, o gatilho dispara uma vez por comando, e a tabela inserted traz todas as linhas daquele comando. Um gatilho escrito como se só chegasse uma linha — com SELECT @numero = NumeroCarteirinha FROM inserted, por exemplo — valida só uma linha da planilha e deixa o resto passar.
    • 
      
  • A ordem do CASE é a ordem das regras. O banco testa da mais grave para a mais simples e para na primeira que vale. Por isso a carteirinha de outro indivíduo é recusada antes de se pensar em troca.
    • 
      
  • Desativar vem antes de inserir. Se a nova carteirinha entrasse primeiro, o indivíduo teria duas ativas por um instante, e o índice UX_Carteirinha_UmaAtiva barraria a importação.
    • 
    

    
As verificações de “repetido na planilha” enxergam as linhas de um mesmo comando. A aplicação deve gravar o arquivo inteiro de uma vez — com inserção em lote ou um parâmetro do tipo tabela — e não linha a linha. Se algo falhar no meio, a importação inteira volta, e nenhum lote fica pela metade.


    
4. Testar com uma planilha de exemplo

    
Um lote pequeno, com uma linha para cada regra, mostra se o gatilho decide como o esperado. No cenário abaixo, os indivíduos 10, 20, 30 e 40 existem no cadastro; o 10 tem a carteirinha A-100 ativa e o 20 tem a B-200 ativa.

    

      

        T-SQL
        
      

      

        

        
INSERT INTO dbo.ImportacaoCarteirinha (LoteID, IndividuoID, NumeroCarteirinha, UsuarioAplicacao)
VALUES
  (1, 10, 'A-101', 'joana.lima'),  -- nova para quem já tem: troca
  (1, 30, 'C-300', 'joana.lima'),  -- primeira carteirinha: importada
  (1, 20, 'B-200', 'joana.lima'),  -- já é dele: nada muda
  (1, 40, 'A-100', 'joana.lima'),  -- pertence ao 10: recusada
  (1, 99, 'D-400', 'joana.lima');  -- indivíduo inexistente: recusada

SELECT IndividuoID, NumeroCarteirinha, Situacao, Mensagem
FROM dbo.LogImportacaoCarteirinha
WHERE LoteID = 1
ORDER BY ImportacaoID;

      

    

    
O log esperado para esse lote:

    

      

        Uma linha de log para cada linha da planilha.
        
          

            IndividuoID
            NumeroCarteirinha
            Situacao
            Mensagem
          

        
        
          
10A-101TROCACarteirinha importada e ativada. A anterior (A-100) foi desativada.

Depois do teste, a Carteirinha deve mostrar a A-100 inativa com data de desativação, e a A-101 e a C-300 ativas com a data da importação. Vale repetir o teste com uma planilha que traga o mesmo número duas vezes, para ver as duas linhas recusadas.


    
5. Mostrar o resultado na aplicação

    
Com o log gravado, a tela de importação não precisa repetir nenhuma regra: ela só lê o que o banco decidiu para aquele lote.

    

      

        T-SQL
        
      

      

        

        
-- Resumo do lote: quantas linhas em cada situação
SELECT Situacao, COUNT(*) AS linhas
FROM dbo.LogImportacaoCarteirinha
WHERE LoteID = @LoteID
GROUP BY Situacao;

-- Linhas que pedem atenção do usuário
SELECT NumeroCarteirinha, IndividuoID, Mensagem
FROM dbo.LogImportacaoCarteirinha
WHERE LoteID = @LoteID
  AND Situacao IN ('RECUSADA', 'JA_CADASTRADA')
ORDER BY ImportacaoID;

      

    

    
O usuário vê, logo depois de enviar a planilha, quantas carteirinhas entraram, quantas trocaram e quais linhas precisam de correção — com o motivo escrito pelo banco. Ele corrige a planilha e envia de novo, sem abrir chamado para o DBA.


    
Resultado

    
As carteirinhas passaram a ser importadas pela aplicação, pelo próprio usuário. Quando havia algum ponto de atenção — carteirinha de outro indivíduo, indivíduo inexistente, número repetido —, o banco gerava o log e a aplicação informava o usuário final.

    
O DBA saiu do caminho da rotina e as regras ficaram num lugar só: no banco, valendo para qualquer forma de entrada. Cada carteirinha passou a ter data de importação, cada troca deixou a anterior registrada como inativa, e cada linha recusada ficou com o motivo guardado.


    
Checklist para um caso parecido

    
    
      
  • Cada situação possível de uma linha listada, com a decisão e a mensagem combinadas com o negócio.
    • 
      
  • Área de importação separada do cadastro oficial.
    • 
      
  • Regras essenciais garantidas por índice único, não só pelo gatilho.
    • 
      
  • Gatilho escrito para várias linhas por comando, sem variáveis que guardam uma linha só.
    • 
      
  • Regras testadas da mais grave para a mais simples.
    • 
      
  • Registro anterior desativado antes de inserir o novo, sem apagar o histórico.
    • 
      
  • Data da importação e lote gravados em cada carteirinha.
    • 
      
  • Log com situação e motivo para cada linha da planilha.
    • 
      
  • Planilha gravada pela aplicação em um único comando.
    • 
      
  • Teste com uma linha para cada regra antes de liberar a tela.
    •
